# Edit CapCut drafts

Before the first CapCut account step in this conversation, check the sign-in with `capcut_get_profile` as the `capcut-connect` skill describes.

Before running any `${CLAUDE_PLUGIN_ROOT}/scripts/` command or ffmpeg, make sure the `capcut-connect` skill's setup check has passed in this conversation.

A CapCut draft is a cloud project that the user can also open in the CapCut web editor. Claude edits it as an STDraft JSON document: download it, change it locally with `scripts/stdraft.mjs`, then save it back. CapCut validates every save.

The user's own edits always win. Drafts also sync to the CapCut desktop app, and if the user saves in the web editor or the desktop app while you are editing, your save is rejected with a version conflict, by design. Simply having the draft open in the desktop app can save new versions.

## Draft sessions

Each draft session (`session_id` from `start_stdraft_session`) is bound to one cloud draft. A new session has no draft until the first save. Keep together, for each session: its `session_id`, the latest `package_id` (the draft version), the latest document saved to a local file, and its editor link. Never mix up a draft `session_id` with a rough-cut editing session or a generation task.

Reuse the session the user is clearly continuing. If several could apply, ask which draft they mean, describing each by its content, not its ID.

## Get the starting document

- **Draft session already in use:** use the document and `package_id` from your last save. If you have none, call `get_stdraft_snapshot` with the `session_id`.
- **Fresh rough cut:** call `video_preview` (on `capcut-cards`) with the rough-cut event's `context` and `resources` unchanged. Its output includes the finished draft as an STDraft string. Then call `start_stdraft_session`. The first save, with an empty `base_package_id`, turns the rough cut into an editable cloud draft.
- **An uploaded video with no draft:** get its width, height and duration from `capcut_batch_media_url` (`vids`). Phone videos are often stored landscape with a rotation flag, so for a local file also check with `ffprobe` when available, and swap width and height when it is rotated 90 or 270 degrees. Ask the user if the shape is still unclear. Run `node "${CLAUDE_PLUGIN_ROOT}/scripts/stdraft.mjs" new --width <w> --height <h> --out <tmp>/draft.json`, then include an `add_video` operation for the clip (`source_end_ms` = its duration) in the first edit round, and call `start_stdraft_session`. The first save, with an empty `base_package_id`, creates the draft.
- **Nothing to start from:** ask the user what to build on, such as a rough cut or uploaded clips.

Save the document as UTF-8 JSON in a temporary folder, for example `<tmp>/draft.json`. Run `node "${CLAUDE_PLUGIN_ROOT}/scripts/stdraft.mjs" summary --in <tmp>/draft.json` to see the timeline, with each segment's id, type, layer, times, source and font. Segments without a timeline (such as `PATCH` segments added by the CapCut desktop app) are listed separately and must be left unchanged. If the summary warns that text has a font that is not a CapCut library font (often a local font path saved by the desktop app), tell the user it may show in a fallback font and offer to set a library font with `update`.

## Edit round

1. **Plan the operations** from the user's request and the summary. Write them as a JSON array to `<tmp>/ops.json`. Supported operations (times in milliseconds):

   | op | Fields | Notes |
   | --- | --- | --- |
   | `add_text` | `content`, `start_ms`, `duration_ms`, optional `position_x`, `position_y` (-1 to 1), `font_size`, `font_color`, `font`, text style fields, `scale`, `rotation`, `opacity` | A title or label on its own layer |
   | `add_captions` | `cues: [{start_ms, end_ms, text, words?}]`, optional `position_y`, `font_size`, `font`, `style`, `layer`, `template` | All cues on the lowest free layer from 1, near the bottom by default (a little higher on a vertical canvas, above the Reels and TikTok caption bar). Use the `capcut-captions` skill to get cues. `words: [{text, start_ms, end_ms}]` (project time, in order, matching the cue's text) gives CapCut word timings, which its caption animations and karaoke styles use; pass them when recognition returned words. `template` is a caption template's `vimo://` source; see **Caption templates and bubbles** below. |
   | `add_audio` | `source`, optional `start_ms`, `duration_ms` (default: to the end), `source_start_ms` (where in the track to start, such as the chorus), `kind` (`music` or `sound`), `volume`, `fade_in_ms`, `fade_out_ms`, `loop` | Music or a sound effect. `source` is the `stdraft_uri` from `capcut-materials` exactly as returned (usually `sid://...`, sometimes `vimo://...`), or an uploaded audio `vid` written as `vid://<vid>`. For a sound effect at a moment, use `kind: "sound"` with `start_ms` and the effect's length as `duration_ms`. |
   | `add_video` | `source` (`vid://<vid>`), `source_end_ms`, optional `source_start_ms`, `start_ms`, `volume`, `overlay`, `layer`, `position_x`, `position_y`, `scale`, `rotation`, `opacity`, `crop`, `background_blur`, `background_color` | Appends to the end of the main track unless `start_ms` is given. With `overlay: true` and `start_ms`, it goes on top of the main track instead (picture-in-picture, such as a face-cam in a corner). |
   | `add_image` | `source` (an uploaded image's `uri`, written as `tos://<uri>`), `duration_ms`, optional `start_ms`, and the same overlay, layout and look fields as `add_video` | A still image on the main track, such as a slide or photo, or with `overlay: true` an image on top, such as a logo or watermark. |
   | `update` | `id`, then any of `content` (text and captions), `texts` (text templates), `source` (swap the music, sound, effect, filter, text template or clip), `intensity` (effects and filters, 0 to 1), `volume` (0 to 4), `font_size`, `font_color`, `font`, `fade_in_ms`, `fade_out_ms`, text style fields (text and plain captions), `crop`, `background_blur`, `background_color`, `blend_mode`, `blend_intensity`, `cutout` (video clips and images) | Changes a segment in place. Never add a new segment and call it an update. `crop: null` removes a crop. Changing a caption's `content` resets its word timings to the whole sentence. Style changes are also written to the per-letter style copies CapCut keeps on text, so they stick. |
   | `place` | `id`, then any of `start_ms`, `duration_ms`, `position_x`, `position_y`, `layer`, `scale`, `scale_x`, `scale_y`, `rotation`, `opacity` | Moves, trims, resizes, rotates or fades a segment. CapCut keeps the main track gap-free, so a main-track clip can't be moved with `start_ms` (move it to an overlay layer instead); trimming one with `duration_ms` moves the clips and everything else after it. |
   | `remove` | `id` | Deletes a segment, with anything attached to it (an effect on that clip, a text's style copies). Removing a main-track clip closes the gap, as CapCut does, and moves everything that started after it (text, captions, audio, effects) earlier by the same amount. The change message lists items that ran across the removed clip, such as its captions: remove or move those, and tell the user. Removing anything else leaves its gap. |
   | `add_transition` | `id` (the earlier clip), `source` (a transition's `vimo://` `stdraft_uri`), optional `duration_ms` (default 500) | A transition from that clip into the clip that starts exactly where it ends, on the same track. Applying one to the same clip replaces it; `source: null` removes it. At most the length of the shorter clip. Clips never move, so if there's a gap, close it with `place` first and say so. Moving or removing either clip later removes the transition. |
   | `add_filter` | `source` (a filter's `vimo://` `stdraft_uri`), optional `intensity` (0 to 1, default 0.6), and `start_ms` with `duration_ms`, or `over` (a segment id, to cover just that clip's time), or neither for the whole video | A colour filter on its own track above what it covers. CapCut's own tools default to full strength; 0.6 is a gentler start. Change it later with `update` `intensity`. |
   | `add_effect` | `source` (a video effect's or face effect's `vimo://` `stdraft_uri`), optional `intensity` (0 to 1; the effect's own strength if left out), and `start_ms` with `duration_ms`, or `over`, or neither | A video or face effect, placed like a filter. For a moment, such as a flash on a beat, give a short range. |
   | `add_text_template` | `source` (a text template's `vimo://` `stdraft_uri`), `texts` (one per slot, in order), `start_ms`, `duration_ms`, optional `position_x`, `position_y`, `scale`, `rotation`, `opacity` | A CapCut text template: a styled, often animated title. Its look comes from the template, so it takes no font or style. CapCut doesn't say how many slots a template has; give one text per line the template's title suggests, and check it in the editor. |
   | `set_canvas` | `ratio` (`9:16`, `16:9`, `1:1`, `4:3`, `3:4`, `2:1`, `2.35:1`, `1.85:1` or `1.125:2.436`), or `width` and `height` | Changes the frame shape, for example a landscape video into a 9:16 reel. Clips keep their size, so add `background_blur` (or a colour) to clips that no longer fill the frame, and move text that would fall outside. |
   | `animate` | `id`, `property` (`position_x`, `position_y`, `scale`, `scale_x`, `scale_y`, `rotation`, `opacity`), `keyframes: [{time_ms, value}]` | **Don't use for now.** It writes keyframes, and CapCut's cloud drafts currently drop all keyframes on save, so nothing animates. Tell the user to add movement or fades in the CapCut editor (Animation or keyframes). |
   | `zoom` | `id`, optional `from`, `to`, `pan`, `pan_amount` | **Don't use for now**, for the same reason: CapCut drops the keyframes it writes. For a slow zoom on photos, point the user to the editor's Animation panel (for example a zoom-in animation) or keyframes. |
   | `duck` | `id` (a music or sound track), `ranges: [{start_ms, end_ms}]` (project time), optional `to` (default 0.25 of its volume), `fade_ms` (default 300) | Lowers the track during each range, for example while someone speaks. It splits the track into back-to-back parts with quieter parts during the ranges and short crossfades between them, because CapCut drops volume keyframes. Ranges closer than two fades merge. Tell the user the music is now several pieces in the editor. |
   | `set_speed` | `id`, `speed` (0.1 to 100; 2 = twice as fast, 0.5 = half speed, 1 = normal) | Constant speed for a video clip. Replaces any ramp. |
   | `speed_ramp` | `id`, then `shape`, or `points: [{x, y}]` | A speed ramp on a video clip. `shape` is one of CapCut's curve presets, named as in its Speed > Curve panel: `montage`, `hero`, `bullet`, `jump_cut`, `flash_in`, `flash_out`. Or it is a basic shape with an optional `peak` (default 3): `ramp_up`, `ramp_down`, `fast_middle` (fast through the middle, normal at both ends, as for a stair climb) or `slow_middle`. For `points`, `x` runs from 0 (start of the clip) to 1 (end) and `y` is the speed there (0.1 to 100). |
   | `reset_caption_layers` | optional `layer` (default 1) | Puts all captions back on the lowest layers, one layer when they don't overlap in time. |

   **Text style fields** (on `add_text`, on `update` for text, and as `style: {...}` on `add_captions`): `text_effect` (a text effect's `vimo://` `stdraft_uri`, CapCut's word art; `null` removes it), `vertical` (true for top-to-bottom text), `bubble` (see below; `null` removes it), `alignment` (`left`, `center`, `right`), `outline` (true or false), `outline_color`, `outline_width` (default 0.06), `shadow` (true or false), `shadow_color`, `shadow_opacity` (default 0.4), `shadow_distance` (default 2), `shadow_blur` (0 to 1, default 0.3), `shadow_angle`, `box_color` and `box_opacity` (a background box behind the text; **CapCut currently saves these but doesn't draw the box**, so don't offer it), `text_opacity`, `underline`, `letter_spacing`, `line_spacing`, `line_max_width` (0.05 to 1, the share of the frame width a line may use), `bold_width`, `italic_degree`. Colours are `#RRGGBB` or `#RRGGBBAA`. The outline and shadow defaults are the values CapCut uses on its own captions.

   **Layout:** `position_x` and `position_y` run from -1 to 1 with (0, 0) at the centre and positive y up; `scale` 1 is the original size; `rotation` is in degrees, clockwise; `opacity` runs from 0 to 1. **Crop** is `[left, top, right, bottom]`, each from 0 to 1. **Background fill** shows behind a clip that doesn't fill the frame, for example a landscape clip in a 9:16 reel: `background_blur` (0 to 1; `true` gives a soft 0.2, and 0.5 already looks strong) or `background_color`.

   **Blend and cutout** (on `add_video`, `add_image` and `update`): `blend_mode` mixes an overlay into the picture below, for light leaks or textures, and `blend_intensity` (0 to 1) sets its strength, which CapCut keeps as the clip's opacity. CapCut stores blend modes as library resources, and only Screen's is known: use `blend_mode: "screen"`. For another mode (CapCut's web editor offers Overlay, Darken and Brighten), ask the user to set it once on any clip in the editor, read the draft, and reuse the `blend vimo://...` source the summary shows. `normal` or `null` removes the blend. `cutout: true` removes the background behind a person (CapCut's smart cutout), for example to put a speaker over a slide. CapCut shows the cutout in its desktop app, but its web preview doesn't, and it's a Pro feature: tell the user to check it in the desktop app.

   **Caption templates and bubbles:** CapCut's material search has no caption templates or text bubbles, so promptcut can't find new ones. It can reuse one already in the draft. Ask the user to apply the look once in the CapCut editor (Captions → Templates, or Text → Bubble) to one caption, then read the draft: the summary shows its `caption template vimo://...` or `bubble vimo://...`. Use that source for the other captions: `template` on `add_captions` (remove the old plain captions first), or `bubble` on `update`. Never invent one. Caption templates don't wrap, so split long captions into short cues (about 28 characters on a vertical frame) or scale them down with `place`; the summary warns about long lines. Bubbles are a Pro feature applied in the desktop app.

   **Vertical videos (9:16):** Instagram Reels and TikTok cover the bottom fifth, the top tenth and the right edge with their own buttons and captions. Keep text and captions inside that, and act on the summary's safe-zone warnings.

   **Layers:** CapCut gives clips, images, text, effects and filters one shared set of layers (audio has its own) and renumbers them on read-back. The operations pick free layers for you; if you set `layer` yourself, choose one that no other clip, image or text uses at that time. `validate` reports clashes, which CapCut would reject with `invalid stdraft`.

   **Always set `font` on text you add or restyle.** Without one, the CapCut web editor and desktop app each substitute their own default font, so the same text can wrap differently. `font` takes a font's `vimo://<id>` `stdraft_uri` from `capcut-materials`. Unless the user named a font, search fonts once per conversation (`search_capcut_material` with `type: "font"`, `top_n: 20`), pick a clean, legible sans-serif from the descriptions, tell the user which one you chose, and reuse it for all new text. If you leave `font` out, promptcut uses CapCut's default library font, so the text still renders.

   **Transitions, filters, effects, text effects and text templates** come from `capcut-materials` (types `transition`, `filter`, `video_effect`, `face_effect`, `text_effect`, `text_template`). Pass each item's `stdraft_uri` unchanged as `source`. Most of these types return a fixed curated list, so choose from the titles and descriptions, tell the user which one you picked and why, and offer the others. Keep filters subtle unless the user wants a strong look. For a text template with no copy given, write a short line that fits the footage, and say what you wrote and where you placed it. Place titles and templates away from faces and existing captions.

   **Keep captions on as few tracks as possible.** CapCut's read-back spreads captions over extra layers, and saving those layers as they are adds a track each time. Whenever the draft has captions, end every operation list with `{"op": "reset_caption_layers"}`, including saves that only change something else. Even so, CapCut usually shows the first caption on a track of its own and the rest together on a second track. Tell the user they can drag the first caption onto the shared track in the editor if they want one track.

2. **Apply locally:** `node "${CLAUDE_PLUGIN_ROOT}/scripts/stdraft.mjs" apply --in <tmp>/draft.json --ops <tmp>/ops.json --out <tmp>/draft-new.json`. On an error, fix the operations and run again. Nothing is written until every operation succeeds and the result validates. Run `summary` on the result and check it matches the request.
3. **Check the version, right before saving:** call `check_stdraft_state` with the `session_id` and your current `package_id` (empty for a new draft). This also shows an "editing" overlay in the web editor for up to 20 minutes, so only call it when you are about to save. If `stale` is true, the user changed the draft in the browser: call `get_stdraft_snapshot`, apply the same operations to that newer document, and tell the user you built on their latest changes.
4. **Save:** call `push_stdraft_snapshot` with `session_id`, `base_package_id` (the version you edited, or empty for a new draft) and `stdraft_json` (the new document as a string).
5. **After a successful save:** keep the returned `server_package_id` as the new version. If `stdraft_json` is returned, save it as the new baseline document, otherwise call `get_stdraft_snapshot`. Tell the user what changed, in plain words, and give them `web_editor_url` with its `web_editor_text` label so they can review and export in the CapCut web editor. Saving a draft does not export a new video file.

   After the first save of a new draft, also tell the user, once per draft:
   - **Names:** CapCut's draft tools can't set a name, and every save resets it. The CapCut desktop app shows "Untitled" and the web editor shows the date and time of the last save (such as 202611111913). A name the user gives the draft is lost at the next save, so they should rename it only after the last change.
   - **Open it on the web first:** open the draft with the web editor link before opening it in the desktop app. Opened only in the desktop app, it gets a numbered name such as "(4)", and closing it there can create a separate copy. Those copies don't receive later saves; check before deleting any.
   - **In the desktop app:** if it asks "Download the latest version before editing?", choose to download and edit. If it then asks to link a missing media file that isn't one of theirs (often a generated cutout), they can cancel; the draft still opens.

## Save errors

| Error | Action |
| --- | --- |
| `STDRAFT_INVALID` | Nothing was saved. Read the validation details, fix the operations or document, and try once more. If it fails again, report the details to the user. |
| `STDRAFT_VERSION_CONFLICT` | Nothing was saved, because the draft changed in the browser. Get the latest snapshot, re-apply the operations, check the summary, then save again with the new `package_id`. |
| `save cloud draft failed` with `ret=2005` | The draft was deleted in CapCut, so this session can't save to it. Tell the user, call `start_stdraft_session` for a new draft, and save the current document with an empty `base_package_id`. |
| Unsure whether a save went through | Call `check_stdraft_state` or `get_stdraft_snapshot` first. Never repeat a save blindly. |
| Login error (for example `check login error` or `get user workspace failed`) | Stop and follow the `capcut-connect` skill. Do not retry or try other tools first. |

## Limits of this version

- Supported: text with styling (outline, shadow, alignment, spacing, vertical text, text effects), captions with word timings, text templates, music (with a start offset) and sound effects at set moments, lowering the music under speech, main-track video clips and still images, overlays and picture-in-picture, crop, background blur or colour fill, blend modes and background removal, size, rotation and opacity, volume and fades, constant speed and speed ramps, transitions, filters, video and face effects, the canvas shape, moving, trimming and removing segments. Caption templates and bubbles only by reusing one already in the draft.

**Tested in a real draft (0.4.0):** transitions (add, replace, remove), filters and their strength, video and face effects, text templates, vertical text, text effects, reusing a caption template or bubble, the canvas shape with background blur, and cutout (desktop app). Fixed in 0.4.1 and not yet rechecked: Screen blend, text effects lasting through later saves, closing main-track gaps, and the music fade-out. Word timings are saved, but CapCut's editor doesn't show them.

**Text styles over many saves:** CapCut keeps per-letter style copies on text and sometimes drops the outline, shadow or text effect from them. Before every save promptcut fills dropped values back in from the text, and says so in the change list.

**Tested in a real draft (v0.3.0):** overlays with position, size and opacity, background blur, size and rotation, crop (saved), music start offset, sound effects and speed changes. **Not kept by CapCut:** keyframes (`animate`, `zoom`) and the text box. Text outline and shadow may look fainter after later saves, because CapCut keeps per-letter style overrides (PATCH segments) that lose detail; if the user notices, restyle the text with `update`.

**Speed changes change a clip's length.** `set_speed` and `speed_ramp` recalculate the clip's length from its speed, and later clips on the main track move to match, along with text, captions, audio and effects that started after the clip. Items that ran across the clip don't move: tell the user when those may now be off, and offer to shift them with `place`. Still images can't change speed. When the user names a CapCut preset ("give it the Hero curve"), use that shape. CapCut's editor smooths the curves, so a preset can look slightly different from picking the same preset in CapCut, while the clip length matches. Speed ramps follow CapCut's draft format, but how a ramp looks hasn't been checked in a real CapCut draft yet: after the first save with a ramp, ask the user to play the clip in the editor and tell you if it looks wrong.
- Not supported: stickers, animations (in, out and loop on clips and text), masks, chroma key and colour adjustments (brightness, contrast, curves). If asked for these, say so, and suggest the CapCut editor. Keyframes are dropped by CapCut (see above).
- CapCut converts drafts between its cloud format and STDraft, so a document read back can differ slightly from the one saved. Always continue from the read-back version.
- Do not use the CapCut desktop app, browser automation or Computer Use to edit drafts.
